四、三个观察

观察 1：缓存命中价差最高达 50 倍

DeepSeek Flash 的输入价：缓存未命中 $0.15，缓存命中 $0.003 —— 差 50 倍。

多轮对话里如果每次都把同一段系统提示词重发，你就在按未命中价反复付费。合理用缓存，这部分能降到 2%。

观察 2：高峰低谷价差 1 倍

DeepSeek 低谷价是高峰的一半。批量任务挪到低谷时段（UTC 04:00–06:00 或 10:00 之后），价格直接减半，没有任何代价。

观察 3：同一家不同型号价格差 5 倍以上

GLM-5.3 输入 8 元，GLM-5.3-Flash 只要 0.8 元 —— 差 10 倍。日常任务用 Flash，复杂任务才用满血版，这是最容易被忽略的省钱点。

五、怎么用这张表

  1. 先算你的量。用 成本计算器 填入你的日请求数和平均 token 长度，得到每月总 token。
  2. 再乘单价。照上表选你要用的模型，用官方价乘出月成本，再乘倍率得到实际支出。
  3. 最后比稳定性。价格只是一维，稳定性、协议兼容、日志可查同样重要，见 选站五项标准。

六、给开发者：机器可读的价格数据

上面这些价格同时提供 JSON 版本，方便程序直接读取，不用手工抄写。

用途地址
价格数据https://huangjinpeng216.github.io/ai-api-relay-pricing-cn/prices.json

数据结构要点：

  • 按 provider 分组，每家带 source_url 和 captured_at，可追溯
  • DeepSeek 区分高峰 / 低谷价，用 off_peak / peak 两个字段
  • 单位统一为「每百万 token」
  • DeepSeek 用 USD，GLM 与 Kimi 用 CNY，字段 currency 标明，未做汇率换算

⚠ 数据只反映抓取当日的官方公示价。价格会调整，生产环境请自行复核，不要直接用于计费。

示例：读取全部模型的最小输入价

const r = await fetch('https://huangjinpeng216.github.io/ai-api-relay-pricing-cn/prices.json');
const { providers } = await r.json();
for (const p of providers) {
  for (const m of p.models) {
    const price = m.pricing.input ?? m.pricing.input_cache_miss?.off_peak;
    console.log(p.provider, m.model_id, price, p.currency);
  }
}
