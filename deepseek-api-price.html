一、计费单位是 token，不是「次」

DeepSeek 的 API 按 token 计费，而且输入和输出分别定价。这跟按条数收费的订阅制完全不同。

项目说明
输入 token你发给模型的全部内容，含系统提示词、历史对话、上传的文档
输出 token模型生成的内容
中文怎么估1 个汉字约 1～2 token，粗略按 1.5 估
英文怎么估1 个单词约 1.3 token

实际体感：一段 500 字的中文问答，输入+输出大约 1200～1500 token。如果你每天聊 50 轮，一个月大概 200 万 token 上下——这个量级决定了不同倍率之间的差价有多大。

二、倍率是什么意思

官方价格以美元计。中转站用「倍率」表示你实际要付的比例：

倍率你要付官方 1 美元的量
1x官方原价1 美元
0.5x官方一半0.5 美元等值
0.1x官方 1 折0.1 美元等值

换算公式：实际花费 = 官方价格 × 倍率。

所以「官网 10 块的量，这边 1 块」这句话的数学含义就是倍率 0.1x。

三、V4.1-Flash-1017 是什么定位

DeepSeek 的 V4 系列目前主要有两条线：

  • 深度推理版：处理复杂报告、长文档分析、数学题更稳，但价格更高、速度更慢。
  • Flash 版（V4.1-Flash-1017）：日常对话、文案生成、写代码、快速问答的首选，响应快、单价低。

两者都能通过 API 调用，模型名不同，计费也不同。写代码和改 bug 这类高频任务，Flash 版的性价比明显更高。

五、影响成本的六个变量

同样一句提问，账单可能差十倍。差别来自这六个地方：

变量怎么影响能不能控
历史对话长度多轮对话每轮都重发前文，输入 token 线性增长能，主动裁剪
系统提示词每次请求固定开销，写得越长每次越贵能，精简
输出长度模型话多，输出 token 直接翻倍能，要求简短输出
模型选择推理版与 Flash 版单价可能差好几倍能，按任务选
失败重试失败的请求可能仍计费，重试等于付两次部分能，设重试上限
平台倍率直接乘在总价上能，但要先确认稳定性

注意排序：前四项的影响通常比倍率更大。只在倍率上省钱，等于在最小的变量上使劲。

六、三个场景的相对成本关系

下面不算绝对金额（各模型官方单价会调整），只说明量级关系，帮你判断钱花在哪：

场景典型用法成本主要花在
问答型每天几十轮对话，每轮几千 token历史对话累积，越聊越贵
工具型写代码、改 bug，一次性任务输入代码 + 输出 diff，上下文相对干净
批量型几百上千条数据处理纯输入量，单价 × 条数

三类里最容易失控的是问答型——不是单价高，是历史越滚越大。很多人月底看到账单惊讶，原因就在这里。

七、具体怎么省钱（按有效性排序）

  1. 裁历史对话。只保留最近 3～5 轮，或把前文总结成一段。这是零成本、效果最直接的一招。
  2. 精简系统提示词。把「你是一个专业的、经验丰富的、乐于助人的助手」这类废话删掉，不影响效果。
  3. 限制输出长度。明确说「用三句话回答」「只给结论和代码」，能砍掉一半输出 token。
  4. 按任务选模型。改错别字用 Flash，复杂重构才用推理版。
  5. 缓存重复请求。批量任务里相同 prompt 的结果存下来，别重复付费。
  6. 最后才看倍率。选稳定的低倍率平台，但前面五条不做，这条的收益会被吃掉。

可以先用 成本计算器 估一下自己现在的量级，再决定要不要优化。

八、常见问题

Q：DeepSeek API 具体多少钱？

官方单价会调整，本页不写死具体数字——写了很快会过期，反而误导。你可以在 DeepSeek 开放平台查到当前单价，然后填进计算器里算自己的账单。

Q：输入和输出价格一样吗？

不一样，通常输出比输入贵。所以「让模型少说废话」比「少发点内容」省得更多——后者受限于任务本身，前者完全可以要求。

Q：为什么我用得不多但账单不低？

最常见的原因是历史对话累积。另一个原因是系统提示词或工具定义太长，每次请求都在为它付费。第三是失败重试。按上面第七节的顺序排查。

Q：0.1x 的倍率能省多少？

能省 90% 的金额。但要注意：如果账单本身只有几十块，省 90% 也只是几十块，不值得为它承担第三方的稳定性风险。量级小的时候，稳定性比价格重要。

Q：Flash 版和推理版怎么选？

日常写代码、改 bug、问答用 Flash 版；需要多步推理、复杂计算、跨文件重构时用推理版。用推理版做简单任务，多花的钱不会让结果更好，只会更慢。

九、一个提醒

倍率不是唯一变量。掺水降智（宣传满血实际降级小模型）会让你的实际成本翻倍，因为你要重试更多次。选站之前，先用一段需要多步推理的 prompt 在官方和该站各跑一次做对比。
