最容易填错的三个地方

1. base_url 到底要不要带 /v1

客户端base_url 填法
Cherry Studio / NextChat / LobeChat / Cline / Cursorhttps://站点.com/v1（带 /v1）
Claude Codehttps://站点.com（不带 /v1）

为什么不一样：Claude Code 会在后面自己拼 /v1/messages，其余客户端会拼 /v1/chat/completions。

填错的典型症状：404，或者报「路径不存在」。如果你填了带 /v1 的地址给 Claude Code，实际请求会变成 /v1/v1/messages。

2. 模型名必须和服务商列表一字不差

不同服务商对同一个模型的命名可能略有差异（大小写、后缀）。以上面填的那串为准，别照抄别处的。

判断方法：访问 站点/v1/models（带上你的 key），返回的列表里才是真实可用的名字。

3. key 前后可能带空格

从网页复制 key 时很容易带上换行或空格，肉眼看不出来，但请求会返回 401。

粘贴后手动按一下 End 键，确认光标紧贴最后一个字符。

配置完先用这条命令验证

别急着在客户端里试，先用命令行确认 key 和地址本身是对的：

curl -s https://你的站点/v1/models -H "Authorization: Bearer sk-你的key"

返回一串 JSON 模型列表 = 地址和 key 都没问题，接下来只需要调客户端的配置。
返回 401 = key 不对或带了空格。
返回 404 = 站点地址填错，或者服务商的 API 暂时不可用。

可以，但不建议。出问题时分不清是谁在消耗额度。
