一句话选型：中文写作、翻译、公文类任务用 GLM-5.3；整本 PDF、长报告、多文档交叉分析用 Kimi K3；写代码和改 bug 用 DeepSeek 的 Flash 版更划算。三者可以同时配在一个客户端里，按任务切换。

二、模型名怎么写

调用时必须用站点列出的准确名称。常见写法（以各站公示为准）：

glm-5.3
glm-5.3-flash
kimi-k3

注意大小写和连字符。自己猜的名字会直接报 model not found，报错排查见 报错大全。

三、调用示例（OpenAI 兼容格式）

curl https://你的站点/v1/chat/completions \
  -H "Authorization: Bearer sk-xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "glm-5.3",
    "messages": [
      {"role": "user", "content": "把下面这段改成正式的公文体"}
    ]
  }'

换成 Kimi 只需把 model 改成 kimi-k3，其余不变。

四、长文档任务怎么用 Kimi

长上下文的正确用法不是「把整个 PDF 塞进去问一句」。更省钱也更准的做法：

  1. 先分段摘要：逐章生成摘要，再把摘要合并
  2. 只喂相关片段：先用关键词检索定位到相关段落
  3. 明确输出结构：告诉它要表格还是分点，能显著减少输出 token

这样即使上下文窗口很大，也能把单次成本压下来。

六、接入第三方网关时注意

  • 确认站点同时支持你需要的模型，不要只看有一个
  • 确认模型名与站点列表一致，不同站可能命名略有差别
  • 长文本任务要留意站点是否有单请求 token 上限
  • 批量任务前先跑 10 次，看延迟分布和失败率
