三个容易忽略的点

  • 「最好的模型」不一定是最适合你的。写周报用推理版，多花的钱不会让周报写得更好，只会更慢。
  • 先看客户端支持什么协议。Claude Code 只能走 Anthropic 协议，选平台前先确认支持。
  • 长上下文不等于省钱。把整本 PDF 塞进去，输入 token 会爆。分段摘要通常更便宜也更准。

四个常见选型误区

误区一：一律用最强/最贵的模型

写周报、改错别字、批量格式化这类任务，用推理版不会让结果更好，只会更慢更贵。模型能力和任务难度要匹配，不是越强越好。

误区二：只看单价，不看实际消耗

单价低的模型如果回答冗长、需要反复追问，实际 token 消耗可能比单价高的模型更多。真正的成本要按「完成同一件事消耗多少 token」来算，可以用 成本计算器 估算。

误区三：以为长上下文就等于省钱

把整本 PDF 塞进对话框，输入 token 会非常大。更省钱也更准的做法是分段摘要再合并，或者先用关键词检索定位到相关段落再喂给模型。

误区四：忽略客户端支持的协议

Claude Code、Codex CLI 这类命令行工具走 Anthropic 协议，只能接提供 Anthropic 兼容接口的服务。选平台前先确认，否则买完用不了。

常见问题

Q：写代码到底该用 Flash 版还是推理版？

日常写代码、读报错、改 bug 用 Flash 版就够，响应快、单价低。只有遇到需要理解复杂业务逻辑、跨文件重构这类任务，才值得切到推理版。

Q：GLM 和 Kimi 能同时用吗？

可以，而且推荐这样做。绝大多数客户端支持配置多个模型，按任务切换即可——写文案用 GLM，读长文档切 Kimi，写代码切 DeepSeek。

Q：怎么判断某个模型是不是被降级了？

用同一段需要多步推理的 prompt，在官方渠道和第三方各跑一次，对比输出质量、思考深度和首字延迟。差距明显就是被降级了。

Q：同一个任务，不同模型的输出差异大吗？

中文写作类任务差异明显（语感、用词习惯不同）；纯代码任务差异较小，更多体现在边界情况的处理和解释质量上。
