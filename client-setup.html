客户端怎么配置第三方 API

Cherry Studio · NextChat · LobeChat · Cline 通用步骤　｜返回比价指南

所有客户端都只认三个值：base_url、api_key、model。配不通几乎都是这三个里有一个不对。

不想对照着填？用客户端配置生成器：选你的客户端、填站点地址，直接生成 base_url、环境变量或 curl 命令，/v1 的加减会自动处理。

一、先拿到三个值

值从哪来长什么样
base_url站点文档或控制台https://站点域名/v1
api_key控制台 → 令牌/API Keys → 新建sk- 开头的一串
model站点模型列表如 deepseek-v4.1-flash-1017、glm-5.3、kimi-k3

注意：模型名必须一字不差，包括连字符和版本号。自己猜的名字 100% 会报 model not found。

二、Cherry Studio

  1. 设置 → 模型服务 → 添加提供商（选 OpenAI 兼容 / 自定义）
  2. API 地址填 base_url
  3. API 密钥填 sk-...
  4. 点「获取模型列表」，或手动添加模型名
  5. 回到对话界面，选刚加的模型

常见问题：获取列表失败多半是 base_url 少了 /v1；列表能拉到但对话报错，检查模型是否在当前分组开放。

三、NextChat（ChatGPT-Next-Web）

  1. 设置 → 自定义接口（Custom Endpoint）
  2. 接口地址填 base_url
  3. API Key 填 sk-...
  4. 模型下拉框里「自定义模型」填模型名，多个用逗号分隔

注意：NextChat 会在 base_url 后面自动拼 /chat/completions，所以不要自己写全路径。

四、LobeChat

  1. 设置 → 语言模型 → OpenAI（或自定义提供商）
  2. 填入 base_url 与 API Key
  3. 在「模型列表」里手动加入模型 ID
  4. 开启「使用客户端请求」以免服务端代理造成额外超时

五、Cline / Roo Code（VS Code 插件）

  1. 选择 API Provider 为 OpenAI Compatible
  2. Base URL 填 base_url
  3. API Key 填 sk-...
  4. Model ID 填准确模型名

如果要接 Claude Code 这类走 Anthropic 协议的工具，需要站点提供 Anthropic 兼容接口，配置方式不同，见 Claude Code 配置教程。

六、多模型怎么组织

建议按用途建多套配置，而不是一套里塞所有模型：

用途模型选择思路
写代码 / 改 bug选响应快、代码能力强的 Flash 类
中文写作、翻译选中文语感好的
长文档分析选上下文窗口大的
批量任务选单价最低的，并做好失败重试

七、配完连不上，按这个顺序查

  1. 用 curl 直接打一次 /v1/models，确认 key 和 base_url 本身是对的
  2. curl 通了但客户端不通 → 客户端路径拼接问题（多写了路径或少了 /v1）
  3. 客户端报 model not found → 模型名不对
  4. 都通但很慢 → 上游拥堵，换模型或换站
  5. 偶发失败 → 加自动重试，不要一次失败就判定站点不可用

报错含义逐个查：AI API 常见报错大全。

八、多客户端共用一套 key 怎么管

很多人把同一个 key 填到五六个客户端里，出问题时分不清是谁在消耗。建议这样组织：

做法好处代价
一个客户端一个 key能看清单个客户端的用量，泄露时只吊销一个要记多个 key
一个用途一个 key按「写代码 / 写文案 / 批量任务」分开，好对账配置稍麻烦
全部共用一个 key省事出事无法定位，只能全换

推荐第二种。多数平台支持给 key 起备注名（如 cursor-mac、batch-job），一眼能看出用途。

九、三个最容易踩的坑

坑一：路径重复拼接

客户端的 base_url 只填到 /v1 为止。如果你填了 https://站点/v1/chat/completions，客户端再拼一次，就变成 /v1/chat/completions/chat/completions，必然 404。

坑二：key 前后带空格

从网页复制 key 时很容易带上换行或空格，肉眼看不出来，但请求会 401。粘贴后手动按一下 End 键检查末尾。

坑三：客户端走了系统代理

如果你电脑开着代理软件（哪怕只是浏览器插件），客户端可能也被接管，导致连不上国内的服务。表现是「浏览器能打开站点，客户端报连接失败」。这种情况在客户端设置里关掉代理，或加白名单。

十、常见问题

Q：一个客户端能配多个站点吗？

多数支持。Cherry Studio 可以添加多个服务商；NextChat 可以配置多个自定义接口。建议把备用站也配上，主站出问题时能马上切。

Q：换站以后聊天记录会丢吗？

不会。聊天记录存在客户端本地，只跟模型服务和接口地址有关，换站不影响历史消息。

Q：手机上能配吗？

能。Cherry Studio、NextChat 都有移动端，配置项和桌面端一致。注意手机上的代理设置可能和电脑不同。

Q：为什么同一个模型，客户端 A 能用客户端 B 不能？

大概率是 B 的路径拼接方式不同，或 B 对模型名的校验更严格。先看 B 的报错码：401 是认证问题（路径或 key），model not found 是模型名问题。

十一、配好之后先做这三件事

  1. 发一句最简单的提问，确认链路通（能回就说明 base_url 和 key 都对）
  2. 发一段需要多步推理的 prompt，确认不是被降级的模型（对比官方输出质量）
  3. 连续用两天，看有没有超时和断流，再决定要不要加量充值

这三步花十分钟，能避免后面花几百块踩坑。
