按报错信息查原因和修法　｜返回比价与选站指南

排查顺序建议：先确认 base_url 路径 → 再确认 key 有效 → 再确认模型名 → 最后看额度与并发。绝大多数问题出在前两步。

401 Unauthorized

含义：认证失败，服务端不认你的 key。

常见原因：

  • Key 复制时带了空格或换行
  • base_url 指向了错误的路径（有的站是 /v1，有的是 /api）
  • Key 已被删除或停用
  • 用了别家站的 key

怎么修：重新复制 key（不要手动输入），确认路径前缀，用 curl 直接测一次：

curl https://你的站点/v1/models -H "Authorization: Bearer sk-xxx"

404 Not Found

含义：路径不存在。

常见原因：

  • base_url 多了或少了 /v1
  • 结尾多了斜杠，变成 //v1
  • 把 /chat/completions 也写进了 base_url（客户端会自动拼）

怎么修：base_url 只填到版本号为止，例如 https://站点域名/v1。

model not found

含义：模型名不存在或当前分组无权限。

常见原因：

  • 模型名拼错（大小写、连字符、版本号）
  • 模型名是你猜的，站点实际叫法不同
  • 该模型在你当前分组未开放

怎么修：从站点文档或控制台的模型列表里复制准确名称。可以调 /v1/models 拉一遍可用列表。

429 Too Many Requests

含义：请求过于频繁，触发限流。

常见原因：

  • 并发太高
  • 单位时间请求数超限
  • 余额不足时部分站也会返回 429（当作软拒绝）

怎么修：加指数退避重试，降到 2~3 并发测试；查余额。

for (let i = 0; i < 5; i++) {
  try { return await call(); }
  catch (e) { if (e.status !== 429) throw e;
    await sleep(1000 * 2 ** i); }
}

insufficient_quota / 余额不足

含义：额度用完。

怎么修：查账户余额和分组额度；确认是否被其他项目共用同一个 key 消耗掉了。

context_length_exceeded

含义：输入超长，超过模型上下文窗口。

常见原因：历史对话全量拼接、贴了超长文档、把整段代码塞进去。

怎么修：裁剪历史、分段处理长文档、改用长上下文模型。

invalid_request_error

含义：请求体格式不对。

常见原因：

  • messages 结构错误（缺 role 或 content）
  • 传了该模型不支持的参数（如 temperature 超范围）
  • JSON 序列化问题，中文没做 UTF-8

连接超时 / 502 / 504

含义：网关或上游不可用。

区分方法：

现象大概率原因
所有模型都超时站点网关故障，或你的网络问题
只有某个模型超时该模型上游拥堵
白天正常、晚上超时站点限流或上游高峰期
偶发 502，重试能过上游不稳定，加自动重试即可

流式输出中断

含义：stream: true 时连接被中途关闭。

常见原因：代理层超时设置过短、SSE 未被正确透传、客户端没处理 data: [DONE]。

报错第一反应

404查 /v1 前缀、去掉多余斜杠
model not found复制准确模型名

insufficient_quota充值或换 key
